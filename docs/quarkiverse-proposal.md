# Quarkus OpenAPI UI Extension Proposal

## Extension Name

**quarkus-openapi-ui**

## Repository Name

`quarkiverse/quarkus-openapi-ui`

## Group ID

`io.quarkiverse.openapiui`

## Artifact ID

`quarkus-openapi-ui`

## Summary

A Quarkus extension that generates static, keyboard-navigable HTML UIs from OpenAPI specifications during build-time and dev-mode, with automatic browser refresh when JAX-RS code changes.

## Description

The OpenAPI UI extension provides a developer-friendly UI for exploring OpenAPI specifications generated by Quarkus applications. Unlike runtime JavaScript-based tools (Swagger UI, Redoc), this extension generates plain HTML + CSS at build time for instant loading and better performance on large specs.

### Key Features

- **Dev-mode integration**: Automatically regenerates UI and refreshes browser when JAX-RS code changes
- **Zero configuration**: Works out-of-the-box with SmallRye OpenAPI (Quarkus's default OpenAPI implementation)
- **Build-time generation**: Produces static HTML/CSS/JS files for fast loading
- **Keyboard-first navigation**: Spacial cursor keys + standard Tab navigation
- **Clean UX**: Details-on-demand design with collapsible sections, method tabs, and response schema exploration
- **Try-it-out modes**: Fetch (live requests), httpie, and curl code generation
- **Dark mode**: Automatic dark mode support via system preferences
- **URL hash navigation**: Bookmarkable deep links to specific operations

### How It Works

The extension hooks into Quarkus's augmentation pipeline via `OpenApiDocumentBuildItem`, consuming the MicroProfile OpenAPI model directly (no HTTP round-trip). During dev-mode, the extension:

1. Watches for code changes via Quarkus's hot-reload mechanism
2. Regenerates the UI HTML when the OpenAPI spec changes
3. Triggers browser auto-refresh via Quarkus's built-in dev-mode live-reload

This provides the same instant feedback loop developers expect from Quarkus dev-mode, but for OpenAPI documentation.

## Quarkus Compatibility

- **Minimum Quarkus version**: 3.x (tested with 3.17.9)
- **MicroProfile OpenAPI version**: 4.0
- **SmallRye OpenAPI**: Works with Quarkus's default SmallRye OpenAPI extension

The extension depends on:
- `io.quarkus:quarkus-smallrye-openapi` (provided)
- `io.quarkus:quarkus-vertx-http` (for serving static resources)

## Technology Stack

**Build-time** (extension processor):
- MicroProfile OpenAPI model (from SmallRye OpenAPI)
- [bulma-java](https://github.com/t1/bulma-java) for HTML generation
- Java 21+

**Runtime** (generated static files served by Quarkus):
- [Bulma](https://bulma.io/) CSS framework
- [HTMX](https://htmx.org/) for dynamic fragment loading
- [highlight.js](https://highlightjs.org/) for response syntax highlighting
- [Font Awesome](https://fontawesome.com/) for icons

All runtime dependencies are bundled as WebJars, served as static resources from META-INF/resources.

## Migration from Current Repo

The extension currently lives in [t1/openapi-ui-next](https://github.com/t1/openapi-ui-next) under the `quarkus-extension` module. The migration will:

1. Preserve git history for the extension modules
2. Update Maven coordinates from `com.github.t1:quarkus-openapi-ui` to `io.quarkiverse.openapiui:quarkus-openapi-ui`
3. Deprecate the original Maven coordinates with a notice pointing to the Quarkiverse version
4. Maintain the core library (`com.github.t1:openapi-ui-core`) in the original repo, as it supports standalone CLI and Maven plugin usage outside of Quarkus

## Benefits to Quarkus Ecosystem

1. **Fills a gap**: Provides a Quarkus-native alternative to runtime JavaScript tools for OpenAPI exploration
2. **Developer experience**: Instant feedback during dev-mode aligns with Quarkus's developer-first philosophy
3. **Performance**: Static generation eliminates client-side OpenAPI parsing overhead
4. **Accessibility**: Keyboard-first navigation makes the UI accessible to power users and assistive technologies

## Prior Art and Alternatives

- **Swagger UI** (runtime JS, slow on large specs, poor keyboard navigation)
- **Redoc** (runtime JS, better static mode but no dev-mode integration)
- **Rapidoc** (runtime JS, similar tradeoffs)

This extension differentiates by:
- Quarkus-native dev-mode integration
- Build-time generation (no runtime parsing)
- Keyboard-first UX design
