# OpenAPI UI Design Review — Spec

Address bugs, UX gaps, and visual design issues identified during the design review of the
generated OpenAPI UI.

## Approach

Fix-first: bugs and interaction feedback first, then visual polish. Each step independently
shippable. All changes are in the `core` module's generator code (`OpenApiUiGenerator.java`)
and a new custom stylesheet.

## Section 1: Bug Fixes

- **Fetch URL resolution** — "Try" mode builds the request URL from `data-base-url` but
  doesn't resolve it relative to `window.location.origin`. Fix: prepend the origin when the
  base URL is a relative path. Change is in the Send click handler (JavaScript).

- **Empty summary em-dash** — When an operation has no summary, the tree item shows
  `pets GET —` with a dangling dash. Fix: skip the em-dash and summary text when the summary
  is empty. Change is in the Java generator.

## Section 2: Interaction Feedback

- **Clipboard feedback** — In curl/httpie modes, clicking Send copies to clipboard with no
  visual indication. Fix: swap the button label to "Copied!" for ~1.5 seconds, then revert.

- **Selected tree item styling** — `aria-selected="true"` is set but has no visual styling.
  Fix: add a background highlight via the custom stylesheet.

- **Hover/focus states on tree items** — Tree items look like plain text. Fix: add cursor
  pointer, hover background, and a visible focus outline replacing the browser default.

- **"Send" vs "Copy" button label** — In curl/httpie modes the button says "Send" but copies
  to clipboard. Fix: JS updates the button label to "Copy" on two triggers: (a) when the mode
  changes, and (b) when a new fragment loads (since fragments are server-rendered with "Send").
  Revert to "Send" when switching back to Try mode.

- **Loading state** — No feedback during fetch in Try mode. Fix: disable the Send button and
  show "Sending..." until the response arrives. Revert on success or error.

- **Fetch error handling** — Network errors and non-2xx responses fail silently. Fix: display
  the error in the response area — show status code and status text when available, or
  "Network error" for connection failures.

## Section 3: Visual Design

- **Method badges** — Color-coded tags in the tree and detail heading. GET=green, POST=blue,
  PUT=orange, DELETE=red. Small `<span>` elements with background color and white text,
  generated by the Java code. Colors defined in the custom stylesheet.

- **Title sizing** — Reduce the operation heading from `is-1` to `is-3` for better proportion.

- **Tree/detail separator** — Add a subtle right border or background difference on the tree
  column to visually separate it from the detail pane.

- **Custom stylesheet** — A new `openapi-ui.css` file, written as a string constant in the
  Java generator (like `TREE_KEYBOARD_JS`), output alongside `bulma.min.css` and `index.html`.
  Linked via `.stylesheet("openapi-ui.css")` in the page builder. Contains: tree item states
  (selected, hover, focus), method badge colors, tree/detail separator, and layout refinements.
  Kept focused — no overriding Bulma defaults unnecessarily.

## Out of Scope

- No new features (auth headers, request body support, response status codes display)
- No response schema rendering changes
- No changes to the landing page (`index.html` in demo module)
