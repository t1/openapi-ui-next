# Request Headers

Add support for custom and spec-documented request headers in the generated UI.

## Three Header Layers

### 1. Spec-Defined Header Parameters

OpenAPI operations can declare parameters with `in: header`. These already flow through
`MethodFragmentGenerator` alongside query/path params. Changes needed:

- Add a `data-param-in` attribute to all parameter input fields (`"header"`, `"query"`,
  `"path"`) so `app.js` can distinguish them. Header params are sent as HTTP headers;
  query/path params continue to work as before.
- Add a **persist checkbox** on each header param field (right-aligned on the label row, next
  to the badges). When checked, the field value is saved to localStorage and restored on load.
- Render enum, boolean, required, and description exactly as for query params — no behavioral
  difference except the transport (`addHeader` vs query string).

### 2. Per-Operation Custom Headers

Below the spec-defined parameters, an **"+ Add custom header"** button lets the user add
arbitrary name/value header pairs for that operation.

- Each row: name input, value input, persist checkbox, remove button.
- Not persisted by default; checking "persist" saves both name and value to localStorage.
- Keyed by operation (method + path).

### 3. Global Headers

A **collapsible "Global Headers" panel** in the detail header area (next to the mode toggle).
Server-generated skeleton in `OpenApiUiGenerator`, populated and managed by `app.js`.

- Each row: name input, value input, persist checkbox, remove button.
- Shows a count badge on the toggle button (e.g. "Global Headers (2)").
- Applied to all "Try it out" requests.
- Collapsed by default.

## Persistence

Per-field localStorage control via a "persist" checkbox. Storage keys use a scan-by-prefix
pattern — no index keys needed:

```
openapi-ui-global-header:<name>           → value
openapi-ui-header:<METHOD>:<path>:<name>  → value
openapi-ui-custom-header:<METHOD>:<path>:<name> → value
```

On page load, scan each prefix to restore persisted values. Unchecking "persist" removes
the localStorage entry immediately.

## Merge Priority

When sending a request, headers are merged with the following priority (highest wins):

1. Per-operation custom headers
2. Spec-defined header param values
3. Global headers

On name collision, the higher-priority value wins silently (no warning).

## CLI Modes (httpie / curl)

Generated httpie and curl commands include all applicable headers from all three layers.
Example curl output:

```
curl -H 'Authorization: Bearer eyJ...' -H 'X-Request-ID: 550e...' http://localhost:8080/pets
```

## Server-Side vs Client-Side Responsibilities

| Component | Generated by | Managed by |
|-----------|-------------|------------|
| Spec-defined header param fields | `MethodFragmentGenerator` (Java) | `app.js` (send as headers, persist) |
| Per-op custom header area | `MethodFragmentGenerator` (Java, skeleton) | `app.js` (add/remove rows, persist) |
| Global headers panel | `OpenApiUiGenerator` (Java, skeleton) | `app.js` (add/remove rows, persist, count badge) |

## Demo App

Extend the demo petstore API to include at least one endpoint with a spec-defined header
parameter (e.g. `X-Request-ID` on `GET /pets`) to exercise the feature end-to-end.

## Out of Scope

- Response headers from the spec definition (only actual response headers after "Try it out")
- Security scheme integration (user types auth headers manually)
- Persist for query/path param values
